# 과학 그림 스타일 정리 (AI스러움 빼기 → 완성본까지)

연구계획서 도식, 학술 인포그래픽, 발표용 SVG·PNG가 "AI가 만든 것 같다", "템플릿 같다"는 인상을 줄 때 쓰는 절차입니다. **내용은 그대로 두고 시각 스타일만** 하나의 언어로 정리합니다. 같은 원칙으로 다음 작업도 다룹니다.

- 효과 평면화, 효과 하나만 흐리게 하기, AI스러운 효과를 의미 있는 표현으로 바꾸기
- 삽입 크기에 맞춘 글자 키우기, 글꼴 교체, 글자 배치 정렬
- 반복 기호(고리 화살표 등) 통일, 빈 여백 채우기, 배경 단색화
- 여러 보드에 같은 변경 반영하기, 아트보드 코멘트로 받은 수정

스타일만으로 해결되지 않는 문제(그림이 하려는 말이 안 보임)는 3a의 이야기 구조 점검으로 넘깁니다. 그림을 처음부터 벡터로 다시 그리는 단계는 `figure-vector-redraw`가 맡고, 이 스킬은 그 뒤 다듬기와 완성을 맡습니다.

## 원칙

- 목표는 AI 흔적을 지우거나 제작 주체를 판별하는 것이 아닙니다.
  - **그림에 맞는 시각 언어 하나를 골라 일관되게 적용**하는 것이 목표입니다.
  - 판별이나 AI 사용 은폐를 요청받으면, 이 스킬은 판별하지 않고 스타일 일관성만 다룬다고 설명합니다.
- "AI스럽다"는 인상은 익숙한 생성형 기본값이 한 화면에 겹칠 때 생깁니다. 예를 들면 다음과 같습니다.
  - 전체에 덮인 따뜻한 색조나 파스텔
  - 모든 요소에 같은 부드러운 그림자와 광택
  - 둥근 카드·배지·리본의 중첩
  - 모두 굵고 비슷하게 큰 제목
  - 의미 없이 번지는 그라데이션(예: 고리 가운데 회오리)
- **효과 하나를 금지하는 공식은 없습니다.**
  - 사람도 거친 선·망점·그라데이션을 쓰고, 사람 작업이 더 조밀하기도 합니다.
  - 매끈한 리메이크가 오히려 AI로 의심받기도 합니다.
  - 판단 기준은 개별 효과가 아니라 **표현 방식의 혼용**과 **근거 없는 기본값**입니다.
- 사람 티를 내려고 노이즈·오정렬·손그림을 임의로 넣지 않습니다. 흰 바탕과 산세리프만 반복해도 또 다른 템플릿처럼 보일 수 있으니, 선택한 언어의 이유를 적습니다.
- **너무 빼지도 않습니다.** 효과를 다 걷어 낸 단색 평면은 "더 이상하다", "너무 단순화됐다"는 반응을 받았습니다. 같은 그림 안의 짝 요소(예: 출력 고리)와 같은 수준의 깊이(테두리·옅은 외곽선·약한 그림자·은은한 그라데이션)를 맞추는 것이 기준입니다.

## 언제 쓰나

- **쓸 때**
  - "AI스러워", "AI 티 안 나게", "템플릿 같아", "스타일만 정리해줘", "더 학술적으로" 같은 요청
  - 이미 있는 그림의 외형 개선: 평면화, 글자 키우기, 글꼴 바꾸기
  - 효과 하나만 조절: "안쪽 회오리 조금만 흐리게"
  - 배치·여백: "글자 배치 다 맞춰줘", "여기 여백이 너무 넓어", "UMAP 위아래로 넓혀줘"
  - 반복 기호: "화살표 크기랑 색 똑같이", "아웃풋처럼 꼬리를 무는 화살표로"
  - 배경: "회로 문양 지우고 단색으로"
  - 변형안의 변경을 원본 보드에도 반영, 아트보드 코멘트로 받은 수정(7절)
  - "깔끔하게 할 아이디어 내봐", "무슨 이야기인지 다시 보고 계획해봐" 같은 제안·계획 요청(3절 끝, 3a)
- **쓰지 않을 때**
  - 그림을 처음부터 다시 그리기 → `figure-vector-redraw`
  - 과학적 내용 검증 (이 스킬은 외형만 다룸)
  - 제작 주체 판별

## 0. 입력 확인

| 입력 | 할 수 있는 일 |
|---|---|
| SVG, HTML, Claude Design 캔버스(.dc.html) | 전체 절차: 진단 → 기존 객체 직접 편집 → 검수 |
| PNG·JPG만 | 진단과 수정안·프롬프트까지. 구조·좌표를 추정해 복원하지 않습니다. 벡터로 다시 그려야 하면 `figure-vector-redraw`를 제안합니다. |

- 먼저 두 가지를 묻습니다.
  - 최종 사용처(논문 단일 칼럼 폭, 슬라이드, 포스터)
  - 기관·학회 서식이 있는지
  - 삽입 크기에서 위계가 보이는지가 마지막 판단 기준입니다.
- **원본은 남기고 변형안을 따로 만듭니다.**
  - Claude Design 캔버스에서는 새 아트보드를 만들어 원본 옆에 둡니다.
    - `canvas.json`에 보드를 추가합니다. x는 원본 너비 + 100입니다.
    - 제목에 안 내용을 적습니다. 예: "A안 · 흰 바탕·평면 패널"
  - 파일 작업이면 `before.*` 사본을 남깁니다.
  - 사용자가 고르기 전까지 원본은 바꾸지 않습니다.
  - 이후 요청이 "A안만"처럼 범위를 정하면 그 안에만 적용합니다.
  - 안이 정해지면 보드를 하나로 합칩니다("Artboard 1로 통일"). 남는 보드는 사용자에게 확인하고 정리합니다.
- 캔버스는 게시 직전에 라이브 파일을 다시 읽습니다. 사용자가 페이지에서 직접 고친 내용을 덮어쓰지 않기 위해서입니다(7절).
- **모호한 요청은 해석을 밝히거나 선택지로 묻습니다.**
  - 방향이 모호한 정도 표현은 현재 상태로 해석합니다.
    - 예: 이미 완전히 불투명한 요소를 "불투명하게"라고 하면 "흐리게(불투명도 낮춤)"로 봅니다.
    - 해석은 답에 한 줄로 밝힙니다.
  - "조금만"은 첫 단계만 적용합니다(예: 1 → 0.6). 더 강한 후보는 비교 이미지로 함께 보냅니다.
  - 범위가 모호한 요청("다른 것도 반영해줘", "모두 반영해줘", "글자 배치 다 맞춰줘")은 앞선 대화에서 후보를 모아 선택지로 묻거나, 범위를 정해 진행하고 그 범위를 밝힙니다.
    - 사용자가 자리에 없으면 가장 보수적인 해석으로 진행하고 그 해석을 밝힙니다.
  - **사용자의 두 요청이 부딪히면 묻습니다.** 예: "여백 줄여줘"(고리 확대)와 "하이픈 넣지 마"(긴 이름을 두 줄로 못 나눔)가 동시에 성립하지 않을 때, 두 안의 대가(빈 공간 몇 px, 약어 사용 등)를 적어 고르게 합니다.

## 1. 보존 계약 — 변경 전에 잠그기

아래 항목을 목록으로 적어 사용자에게 보여주고, 원본 사본을 남깁니다.

- 모든 원문·수치·단위·수식·기호·범례와 패널의 의미
- 데이터 좌표(산점도·UMAP·공간 지도), 단백질 구조 같은 생물학적 대상의 형태
- 네트워크의 노드·간선 수, 연결 관계, 화살표 방향, 처리 단계의 순서와 패널 사이의 연결
- 색이 범주나 값을 뜻하면 그 대응 관계(데이터 그림 내부 색은 바꾸지 않음)
- 판독이 어려운 부분은 추정하지 않고 "확인 필요"로 표시

문구 축약이나 수정은 스타일 변경과 분리해, 따로 승인받습니다. 약어(α-KG, Oligo)로 줄이는 것도 문구 변경입니다.

## 2. 스타일 진단

1. 자동 집계를 실행합니다.
   - 데이터·도식 본체는 집계에서 뺍니다. 중첩 `<svg>`이거나 `--skip`과 일치하는 그룹이 본체로 취급됩니다.
   - 틀(배경·패널·라벨·화살표·장식)만 셉니다.
   ```bash
   python3 scripts/style_audit.py figure.svg --skip "umap|network|structure" --md audit_before.md
   ```
2. 화면을 보고 아래 7개 축을 점검합니다. 자동 집계는 단서일 뿐이고, 판단은 화면으로 합니다.
3. 결과를 "관찰 → 왜 기본값처럼 읽히는지 → 제안" 형식으로 3–6개 정리합니다. 기본 우선순위는 다음과 같습니다.
   1. 배경과 패널
   2. 바깥 장식(회로 무늬, 배지, 리본처럼 데이터가 아닌 것)
   3. 표현 방식 혼용
   4. 제목과 라벨 위계

| 축 | 기본값처럼 읽히는 조합 | 대안 방향 | 자동 집계 단서 |
|---|---|---|---|
| 팔레트 | 배경부터 요소까지 같은 따뜻한 색조·파스텔 막 | 배경과 의미색 분리, 역할별 소수 색 | 배경 채도, 색상군 수, 따뜻한 계열 비율 |
| 음영·재질 | 성격이 다른 요소에 같은 부드러운 그림자·볼륨·광택 | 평면 기호 또는 의도한 재질 하나로 통일. 실제 3D 구조는 유지 | 그림자 사용처, 그라데이션·흐림 필터 수 |
| 텍스처 | 화면 전체에 균일한 입자·안개·종이 느낌 | 목적 없으면 제거, 쓰면 한 체계로 제한 | 패턴, feTurbulence |
| 외곽선 | 흐릿한 경계, 또는 모든 요소에 같은 두꺼운 선 | 역할별(패널·데이터·화살표) 두께와 끝모양 | 선 두께 종류 수 |
| 도형·장식 | 둥근 카드·배지·리본·말풍선의 중첩 | 패널 모양 1종, 모서리 반경 1값 | 반경 종류, 장식 이름 |
| 타이포그래피 | 모든 소제목이 굵고 효과가 많아 비슷하게 눈에 띔 | 제목·섹션·본문·주석 3–5단계, 굵기 규칙 | 글자 크기 종류, 굵은 글자 비율, 글꼴 수 |
| 레이아웃 | 같은 카드 반복으로 모든 구역이 같은 무게 | 내용량에 맞춘 구역 비중, 정렬된 격자 | 화면 확인 |

## 3. 시각 언어 고르기

두 안을 짧게 제시하고, 사용자가 고르거나 기관·브랜드 레퍼런스를 줄 수 있게 합니다.

- **A안 — 학술 벡터**
  - 흰색 또는 아주 옅은 단색 바탕
  - 평면 패널: 얇은 테두리, 그림자 없음 또는 아주 약하게 1종
  - 한 계열 강조색(예: 파랑), 범주색은 유지
  - 가는 패널선
- **B안 — 편집 디자인**
  - 선 중심 표현
  - 2–3개 인쇄색
  - 제목과 세부 정보의 큰 크기 대비

고른 뒤 **스타일 토큰 표**를 만들어 확정합니다. 아래 예시 열은 실제 완성본(Space2 TCA 도식)의 최종값입니다. 출발점으로만 쓰고 그대로 복사하지 않습니다.

| 토큰 | 정할 값 | 완성본 예 (1920×1080 슬라이드 그림) |
|---|---|---|
| 배경 | 색 1개 | 단색 `#f3f5f8` 위에 흰 카드. 회로 무늬·방사형 그라데이션은 최종적으로 삭제 |
| 색 역할 | 패널 면·테두리, 강조색, 범주색(기존 유지), 글자색 | 패널 `#ffffff` / 테두리 `#d0d7de`, 본문 `#1a1a1a`, 열 제목·캡션·부제 `#4b5661` |
| 패널 문법 | 모양 1종, 모서리 반경 1값, 테두리 두께, 그림자 정책 | 둥근 사각형, 반경 8, 1px, 그림자 없음. 패널 안 이중 테두리는 삭제 |
| 선 체계 | 패널선 / 데이터선 / 화살표 두께, 화살촉 모양 1종, 끝모양 | 흐름 화살표는 단색 평면. 고리 화살표는 4f의 한 문법(테두리·옅은 외곽선·약한 그림자) |
| 글자 단계 | 3–5단계 크기, 단계별 굵기, 줄간격, 최소 크기 | 열 제목 36b · 하단 그림 제목 36(앞부분 굵게) · 카드 제목 28b · 부제·캡션 25 · 범례 제목 28b · 범례 24 · 대사물 라벨 23 · 플롯 주석 20 · 고리 중앙 32–36b |
| 질감·장식 | 쓸지 여부와 범위 | 없음. 축·색 막대 high/low·패널 문자·주석 지시선·"illustrative values"도 사용자가 지움 |

**장식 처리는 세 갈래로 제시합니다.**

1. 지우기
2. 흐리게: 불투명도 0.3–0.4로 낮추고 그라데이션·흐림·빛줄기를 빼서 선만 남깁니다.
3. 유지

- 흐리게 한 장식은 마지막에 지워지는 경우가 많았습니다. 장식은 처음부터 지우기 쉬운 한 요소(배경 `<svg aria-hidden>` 하나)로 묶어 둡니다.
- 장식을 지우거나 흐리게 하면, 그 장식을 보이게 하려고 둔 여백의 이유가 사라집니다. 이때 좌우 여백을 다시 맞춥니다. 예: 왼쪽 64 / 오른쪽 40 → 양쪽 52.

**아이디어를 요청받으면**

- 지금 그림을 다시 렌더링해 보고, 화면에서 근거를 찾은 제안만 냅니다.
- 제안은 세 층으로 나눕니다.
  1. 바로 적용 가능(내용 변경 없음): 장식 제거, 카드 제목 형식 통일, 굵은 제목 단계 줄이기, 흐름 화살표 약하게
  2. 색은 의미에만: 뜻 없는 색은 회색으로, 같은 범주는 그림 전체에서 같은 색. 데이터 색 변경은 승인 필요
  3. 과감한 안: 테두리 없는 레이아웃, 패널 문자(a–f), 조밀한 라벨 줄이기, 글꼴 교체
- 항목마다 "지금 → 제안 → 예"를 한두 줄로 쓰고, 내용 변경 여부를 표시합니다.
- 추천 조합 하나와 "원본 옆 비교 보드로 만들기" 제안으로 끝냅니다.
- "덜 AI스럽게"로 넣은 사람 손맛 요소(왼쪽 정렬 제목, 패널 문자, 주석 지시선, 도구 흔적)는 사용자가 하나씩 지운 경우가 많았습니다. 넣을 때는 각각 따로 지울 수 있는 요소로 넣고, 지워지면 다시 넣지 않습니다.

### 3a. 이야기 구조 점검 — 요청받았을 때만, 별도 계획으로

스타일을 아무리 정리해도 그림이 하려는 말이 안 보이면, 구조를 다시 봐야 합니다. 이 단계는 내용과 배치를 바꾸므로 스타일 작업과 분리해 계획으로 내고 승인받습니다.

1. **한 문장으로 적기:** 제목·캡션에서 출발해 그림의 말을 한 문장으로 씁니다.
   - 예: "TCA 회로의 각 반응이 어디서, 어떤 세포에서 일어나는지를 세 데이터와 그래프 모델로 추론한다."
2. **주장과 증거 짝짓기:** 제목이 약속하는 주장마다 그것을 보여주는 그림 요소를 짝짓고 빈칸을 찾습니다.
   - 예: 제목은 "Spatially resolved"인데 출력에 조직 지도가 없음.
3. **패널 사이 관계 점검**
   - 같은 대상이 입력과 출력에서 다른 모양으로 그려졌는지
   - 화살표가 짝짓는 관계가 패널 설명과 맞는지
   - 그래프의 점·색이 무엇인지 그림 안에 적혀 있는지
4. **구성 원칙으로 제안하기**
   - 역할 꼬리표: 입력마다 맡은 물음을 붙입니다. 예: WHAT(어떤 반응) · WHO(어떤 세포) · WHERE(어디)
   - 같은 모양 두 번: 입력과 출력에 같은 도형을 같은 문법으로 둡니다. 모델이 더한 정보는 색 변화로만 보이게 합니다. (완성본에서 사용자가 직접 요구한 것: 입력 고리도 출력처럼 "꼬리를 무는" 화살표, 4f)
   - 답을 주인공으로: 출력 패널을 가장 크게 둡니다. 열 폭은 내용에 맞게 다르게 나눕니다(출력 열이 가장 넓게).
   - 색은 의미에만 씁니다.
5. **와이어프레임은 ASCII로만**
   - `+`, `-`, `|`만 씁니다.
   - 상자 그림 문자(─│┌)와 그리스 문자는 한글 글꼴에서 두 칸 폭이 되어 줄이 어긋납니다.
   - 줄 길이가 모두 같은지 스크립트로 확인합니다.
6. **결정할 것을 따로 묻기**
   - 실제 방법(모델) 흐름: 추정하지 않습니다. 추정으로 그릴 때는 추정이라고 밝힙니다.
   - 원본에 없던 내용(예: 예측 지도)을 더할지. 원본에 없는 내용을 넣었다가 "이런 내용이 없어"로 지워진 적이 있습니다. 기본은 넣지 않는 것입니다.
   - 용도: 발표(단계별로 나눠 보여주기) / 논문(패널 문자, 제목은 캡션으로)
7. **예시 값은 알려진 지식을 따르기:** 무작위로 칠한 색은 전문가 눈에 바로 띕니다. 예시 값이라는 표시를 둘지는 사용자에게 맡깁니다(완성본에서는 사용자가 지움).
8. **진행:** 실제 문구를 넣은 회색 와이어프레임 보드로 구조부터 합의하고, 그다음 상세를 그립니다.
9. **검증 — 5초 테스트:** 처음 보는 사람이 5초 뒤 그림을 한 문장으로 말할 수 있는지 봅니다.

## 4. 적용

순서를 지킵니다.

1. 배경
2. 팔레트(의미 없는 색만)
3. 패널(모양·반경·테두리·그림자)
4. 장식(데이터가 아닌 것으로 확인된 것만, 사용자 확인 후)
5. 선·화살표
6. 글자
7. 구역 비중·정렬(4h), 여백(4i)

- 기존 객체를 편집하고, 텍스트는 편집 가능한 상태로 둡니다. 다시 그리지 않습니다.
- 데이터 그림 내부(UMAP 점, 단백질 리본, 공간 지도, 네트워크)는 기본적으로 손대지 않습니다.
  - 서로 다른 렌더링 방식이 필요한 대상이므로, 억지로 같은 아이콘 양식으로 맞추지 않습니다.
  - 대신 **주변 틀·라벨·화살표**를 통일합니다.
  - 예외는 아래 4a, 4i입니다.
- 네트워크 뒤 반투명 색 영역은 집단 표시인지 먼저 확인합니다. 집단 표시라면 의미를 유지한 채 경계를 또렷하게 하거나 면색을 절제합니다.
- 레이아웃을 바꿔도 그룹 소속과 연결 관계는 그대로 둡니다. 라벨 위치는 스타일 변경 뒤 다시 확인합니다(선 두께나 글자 크기가 바뀌면 라벨이 선에 붙을 수 있음).
- 변환은 **원본에서 다시 만들 수 있는 스크립트**로 둡니다. 원본이 바뀌면 스크립트를 다시 돌립니다. 대상 변환은 다음과 같습니다.
  - 배경색 교체
  - 패널 스타일 치환
  - 장식 제거·흐리게
  - 자산 이미지 교체
  - 좌표 이동
  - 단, 사용자가 캔버스를 직접 고치기 시작하면 생성 파이프라인을 다시 돌리지 않습니다(7절).
- 여백을 바꿔 좌표를 옮길 때는 배경 장식도 같은 열의 것만 함께 옮깁니다. 예: 왼쪽 열 요소만 −12.

### 4a. 도식 자산 안의 효과 평면화 — 사용자 승인 후에만

**대상**

- 네트워크·GNN 같은 도식 그림 안의 부드러운 효과는 데이터가 아니라 스타일입니다.
- 예: 노드 후광, 허브 발광, 굵은 밑깔림 선, 하이라이트 선, 작은 흰 광택점, 영역 외곽 번짐
- 바깥 틀만 평면이고 안쪽이 번들거리면 혼용이 남습니다.
- 그래서 사용자에게 **무엇을 지우는지 목록으로** 묻고 승인받은 뒤 고칩니다.

**효과 요소 찾기**

- 효과 요소는 속성으로 골라 스크립트로 지웁니다.
  - 큰 `stroke-width`의 밑깔림
  - 낮은 `opacity`의 원
  - `url(#…glow|halo)` 채움
  - 반지름 3 안팎의 흰 점
- 종류별로 지운 개수를 보고합니다.

**함께 바꾸는 것**

- 영역 면은 더 옅은 같은 색조 + 같은 색조의 2px 테두리로 바꿉니다. 집단 의미는 유지됩니다.
- 효과가 빠져 흐려진 안쪽 선은 불투명도를 올려 판독성을 맞춥니다. 예: 0.45 → 0.85.

**검수**

- 노드·주 간선·연결선·노드 채움색 개수가 그대로여야 합니다.
- `preserve_check.py`를 자산 쌍에 `--art`(노드·간선 그룹)와 `--ignore-faint 0.3`으로 돌립니다(5절).

### 4b. 글자 키우기 — 삽입 크기 기준

**최소 크기 계산**

- 최종 삽입 크기로 배율을 계산합니다. 예: 1920 폭 그림을 슬라이드 절반(약 948px)에 넣으면 ×0.49입니다.
- 가장 작은 글자가 삽입 크기에서 약 10px 이상이 되도록 원본 최소 크기를 정합니다. 위 예에서는 20–22px입니다.

**조금씩 키우기("글자 조금씩만 키워줘")**

- 역할별로 1–2px씩 올리고, 사용자가 옮긴 위치는 기준점으로 지킵니다. 가운데 정렬은 가운데, 오른쪽 정렬은 오른쪽 끝, 왼쪽 정렬은 왼쪽 끝을 고정합니다.
  ```bash
  python3 scripts/bump_text.py board.dc.html out.dc.html roles.json --font-regular R.ttf --font-bold B.ttf
  ```
- 제목이 커지면 바로 아래 부제를 그만큼 내립니다. 카드 끝에 걸리는 긴 라벨은 카드 안쪽 12px 안으로 당깁니다.
- 사용자는 이후 열 제목·하단 제목을 36px로 더 키웠습니다. 제목 단계는 생각보다 크게 잡아도 됩니다.

**공간 확보**

- 공간은 글자를 줄이지 않고 도식 간격을 늘려 확보합니다. 예: 그래프 노드의 세로 간격 1.15 → 1.3배.
- 라벨이 선과 겹치면 노드 몇 개만 조금 옮기거나 간선 곡률을 바꿉니다. 연결 관계와 방향은 그대로 둡니다.

**데이터 그림 안 라벨**

- 플롯 안 라벨이 커진 크기로 들어가지 않으면 별도 단계를 둡니다. 예: 플롯 주석 20 / 도식 라벨 22.
- 그래도 안 들어가면 플롯을 조금 줄이고(예: 0.95배) 카드 가운데에 맞춥니다.
- **하이픈으로 단어를 끊지 않습니다.** "Oligo-/dendrocyte", "α-Keto-/glutarate"처럼 줄을 나누는 하이픈은 사용자가 거절했습니다. 대신 배치를 바꿉니다.
  - 라벨을 군집 아래로 옮기기, 이웃 군집을 옮겨 한 줄 자리 만들기(설명용 그림일 때만, 4i)
  - 도식을 조금 줄이기
  - 그래도 안 되면 약어(α-KG, Oligo)를 선택지로 묻기(문구 변경이므로 승인 필요)
- 이름 자체의 하이픈(α-Ketoglutarate, Succinyl-CoA)은 그대로 둡니다. 꼭 필요하지 않은 복합어 하이픈도 빼는 쪽을 사용자는 선호했습니다(예: 사용자가 직접 "cell-type" → "cell type"으로 고침).

**확인**

- 바꾼 뒤 라벨과 선·테두리 사이 간격을 다시 봅니다.
- 라벨이 어느 대상을 가리키는지 모호하지 않은지도 확인합니다.

### 4c. 글꼴 바꾸기

1. **파일 받기**
   - 패키지 저장소에서 받습니다. 예: `npm pack @kfonts/nanum-barun-gothic`, `@fontsource/*`
   - 받은 파일은 새 빈 폴더에 풀고, 실행하지 않고 읽기만 합니다.
2. **라이선스 확인**
   - 패키지 메타데이터와 글꼴 내부 name 테이블(저작권 nameID 0, 라이선스 nameID 13)을 둘 다 봅니다.
   - 둘이 다르면 그대로 보고합니다.
   - 예: 패키지는 OFL-1.1, 글꼴 내부는 "NHN Corporation" 라이선스.
   - 법률 판단은 하지 않습니다.
3. **적용**
   - woff2 일반체·굵은체를 asset으로 올립니다.
     - 캔버스: Artifact 게시 `asset: true`, `file_paths`
   - `swap_font.py apply`로 `@font-face`(`font-display:block`)를 넣습니다. 기존 글꼴 목록은 대체 글꼴로 남깁니다.
   - 한글 글꼴은 서브셋하지 않고 전체를 올립니다(굵기당 약 1.5MB). 나중에 문구를 고칠 때 글자가 빠지지 않게 하기 위해서입니다.
   - 텍스트는 윤곽선으로 바꾸지 않습니다.
4. **다시 재기**
   - `swap_font.py measure`로 글자 폭 변화와 넘침을 봅니다.
   - 글자 폭으로 정한 것들은 새 글꼴 파일로 다시 계산합니다. 레이아웃 생성기가 있으면 글꼴 경로를 바꿔 다시 실행합니다.
     - 라벨 위치(오른쪽 정렬·가운데 정렬 기준점)
     - 상자 폭
     - 라벨 여백으로 정한 도식 배율
5. **보고**
   - 글리프 차이를 적습니다. 예: 나눔바른고딕은 하이픈이 넓습니다. 일반체는 Arial보다 넓고(α-Ketoglutarate 22px에서 +14px), 굵은체는 오히려 좁습니다.
   - 부수 효과를 적습니다. 예: 라벨이 넓어져 회로 그림이 5–7% 작아짐.
   - 되돌릴 방법도 제안합니다. 예: 안쪽 여백을 줄여 크기 회복.

### 4d. 효과 하나만 조절하기 — 흐리게·진하게

1. 자산 SVG에서 그 효과를 그리는 그룹을 id·data-name으로 찾습니다. 렌더링해 정확히 그 그룹인지 확인합니다.
2. 불투명도는 **그룹 하나에** 겁니다. 자식마다 걸면 겹친 조각의 경계가 얼룩으로 보입니다.
3. 후보 3–4개를 실제 표시 크기로 나란히 그려 보냅니다.
   ```bash
   python3 scripts/effect_opacity.py ring.svg --group "color_flow" --values 1 0.6 0.45 0.35 \
           --out variants/ --size 424x435 --png
   ```
   - "조금만"이면 첫 단계를 적용하고 비교 이미지를 함께 보내 고르게 합니다.
4. 고른 값의 SVG를 새 asset으로 올리고, 그 보드의 주소만 바꿉니다.
   - 캔버스에서는 게시 호출의 `edits`로 `url(/_blob/…)` 한 줄만 교체합니다.
5. 같은 자산을 다른 보드도 쓰는지 확인합니다(4e).

### 4e. 여러 보드에 반영하기

**공유 자산**

- 같은 asset을 여러 보드가 참조할 수 있습니다. 한 보드의 주소만 바꾸면 나머지 보드는 이전 그림 그대로입니다.
- "모두 반영"이라는 요청이면 모든 보드에서 그 id를 찾아 함께 바꿉니다.
  ```bash
  grep -o '/_blob/[0-9a-f]\{32\}' project/*.dc.html | sort | uniq -c
  ```
- 원본 보드를 남겨 두기로 한 경우에는 무엇을 바꾸지 않았는지 답에 적습니다.

**변형안의 변경을 원본에도**

변형안이 원본과 같은 바탕에서 만들어졌다면 다음 순서로 옮깁니다.

1. 원본 보드를 백업합니다(로컬 사본 + 그때의 판 번호).
2. 원본과 변형안을 비교해, 차이가 모두 변형 작업에서 온 것인지 확인합니다. 원본에만 있는 사용자 수정이 있으면 먼저 변형안에 합칩니다.
3. 변형안 파일을 원본 경로에 복사합니다. 원본의 `<title>`과 보드 제목은 유지합니다.
4. `preserve_check.py`로 백업과 새 원본의 글자·도식 수가 같은지 확인합니다.
5. 두 보드가 같아졌다는 점, 이전 원본은 판 기록에서 되돌릴 수 있다는 점을 알립니다.

### 4f. 반복 기호 통일 — 고리 화살표

AI 그림의 순환 도식은 화살표 수가 단계 수와 다르고(TCA 8단계에 9개), 길이·색이 제각각인 경우가 많습니다.

- **한 단계 = 화살표 하나.** 같은 크기·같은 색·같은 테두리로 360/N°씩 고르게 둡니다. 첫 이음매(첫 대사물)는 맨 위(−90°)입니다.
- **같은 그림 안의 짝 고리와 같은 문법**을 씁니다. 출력 고리가 "꼬리를 무는" 화살표(화살촉이 다음 화살표 꼬리의 V자 홈에 들어감)면 입력 고리도 그렇게 그립니다. 화살촉과 홈 사이 틈은 일정한 폭(약 1.6°)으로 둡니다.
- **색:** 의미 없는 순환이면 중립색 하나. 단, 회청색 단색은 밋밋하다는 반응이었고, 연한 노랑(꼬리 크림 → 머리 진한 노랑 그라데이션)에 따뜻한 갈색 테두리가 최종 선택이었습니다. 출력 쪽 의미색(빨강·파랑)과 겹치지 않는 색을 고릅니다.
- **깊이:** 테두리 1.6 + 옅은 외곽선(회색 3.4px, 불투명도 0.5) + 약한 그림자(dx 1.4, dy 2, blur 1.5, 0.3) + 바깥 가장자리 흰 하이라이트. "너무 단순화"라는 반응이 나오면 이 순서로 더합니다.
- 후보 2개(예: 어두운 테두리 / 갈색 테두리)를 실제 크기 비교 이미지로 보내 고르게 합니다.
  ```bash
  python3 scripts/ring_arrows.py ring.svg --steps 8 --style chain                       # 완성본 기본값
  python3 scripts/ring_arrows.py ring.svg --style gap --flat --fill "#dfe5ea" --border "#7d8a94,1.2"
  ```
- 같은 캔버스 크기·중심·반지름을 지키면 기존 `<img>` 상자에 그대로 들어갑니다. 바꾼 뒤 라벨은 4h의 간격 규칙으로 다시 맞춥니다.

### 4g. AI스러운 효과를 의미로 바꾸기

- 고리 가운데 흐릿한 회오리처럼 뜻 없는 효과는 흐리게(4d)만으로 끝나지 않을 수 있습니다. 그 자리를 **데이터가 말하는 것**으로 바꿉니다. 예: 바깥 줄 성상세포(파랑), 안쪽 줄 뉴런(빨강)의 두 줄 활동 띠, 진하기는 각 칸의 화살표 색을 따름.
- 이때도 너무 딱딱하면 안 됩니다. 단색으로 칸을 나눈 띠는 "더 이상하다"는 반응이었고, 경계를 6px 부드럽게 푼 은은한 그라데이션(불투명도 0.5)이 최종 선택이었습니다. 0.45/0.5/0.6 후보를 비교 이미지로 냅니다.
- 범례 색과 같은 계열을 써서 범례를 새로 만들지 않습니다.

### 4h. 글자 배치 정렬 패스("글자 배치 다 맞춰줘")

숫자 규칙 하나로 모두 맞춥니다. 화면 감으로 하나씩 옮기지 않습니다.

1. **왼쪽 축 하나:** 카드 제목·부제·캡션·범례가 모두 카드 안쪽 16px에서 시작합니다. 열 제목도 같은 축(카드 왼쪽 + 16)에 둡니다.
2. **줄 높이 하나:** 이웃한 열의 위·아래 카드가 나뉘는 높이를 같게 맞춥니다(예: 위 카드 끝 524, 아래 카드 시작 540). 그러면 아래 줄 카드 제목들이 한 줄에 섭니다.
3. **아래 기준선 하나:** 캡션·범례의 마지막 줄을 열마다 같은 높이에 둡니다(카드 바닥에서 13px).
4. **카드 폭 다시 나누기:** 제목이 테두리에 붙으면(오른쪽 여백 < 16) 이웃 카드와 폭을 다시 나눕니다. 이웃 그림의 왼쪽 끝이 제목 축에 오게 하면 한 번에 두 가지가 맞습니다.
5. **고리 가운데 글자:** 잉크 상자의 중심이 아니라 고리의 기하 중심(띠·원의 중심)에 둡니다. 화살촉 때문에 잉크 상자는 한쪽으로 치우칩니다.
6. **고리 라벨 간격 하나:** 라벨 글자 잉크와 고리 잉크 사이 최소 거리를 모든 라벨에서 같게(16px) 맞춥니다. 규칙적인 고리는 마주 보는 라벨끼리 높이를 같게 합니다.
   ```bash
   python3 scripts/ring_label_gap.py board.dc.html blobs.json out.dc.html --ring-alt "TCA cycle schematic" \
           --labels "Citrate,Isocitrate,..." --region 60,170,600,480 --centre 299.6,328.5 --rule axes
   python3 scripts/ring_label_gap.py board.dc.html blobs.json out.dc.html --ring-class ring-art \
           --labels "..." --region 1258,166,1866,906 --centre 1549.8,543.2              # 불규칙 고리: radial
   ```
   - 2배 렌더링의 반올림 때문에 ±0.7px 차이는 남습니다. 한 번이면 충분합니다.
7. **카드 안 그림 묶음:** 그림과 라벨 전체의 잉크 범위를 카드 안 남은 공간(제목 아래 ~ 카드 바닥) 가운데에 둡니다.
8. 줄을 맞추며 생긴 빈 장식 선(배경 회로 등)이 카드 틈 가운데에 오도록 함께 옮깁니다.
9. `preserve_check.py`로 글자 수가 그대로인지 보고, 전후 비교 이미지를 보냅니다. 마지막에 남은 작은 차이(예: 색 막대 오른쪽 여백 22 vs 16)는 고치지 않고 한 줄로 알립니다.

### 4i. 여백 채우기 — "여기 여백이 너무 넓어"

- **먼저 무엇이 크기를 막는지 계산합니다.** 둥근 도식은 양옆 라벨이 카드 테두리에 닿는 순간이 한계입니다(예: 출력 고리는 1.0배가 한계, 하이픈 줄바꿈 없이는 더 못 키움). 한계와 대가를 숫자로 보여주고, 다른 수단(열 간격 64 → 48, 범례를 도식 아래로 묶기)을 선택지로 냅니다.
- **이웃 패널에 맞춥니다.** 첫 시도에서 UMAP을 카드 높이 전체로 늘리자(군집 간격 2배) "너무 넓혔다"는 반응이었습니다. 옆의 공간 지도와 같은 크기·같은 아래 선(이미지 바닥 높이 일치)이 맞는 정도였습니다. 강도 2–3개를 같은 화면에 나란히 그려 고르게 합니다.
- **산점도를 세로로 늘리지 않습니다.** `scaleY`는 군집을 납작하게 만듭니다. 군집(섬)을 찾아 섬 중심 사이 간격만 벌리고(KY 1.3–1.4), 섬 자체는 1.1–1.15배만 키우고, 점 반지름도 같이 키웁니다.
  ```bash
  python3 scripts/umap_spread.py board.dc.html umap.svg out.svg out.dc.html --img-alt "UMAP of single-cell clusters" \
          --labels "Exc. neuron,..." --k 1.02,1.35 --s 1.1,1.15 --bottom 903 --card 52,324
  ```
- 라벨 자리를 만들려고 군집을 옮기는 것(`--move "violet:-61,6"`)은 **설명용(illustrative) 그림일 때만** 합니다. 실제 데이터 임베딩이면 군집 좌표를 바꾸지 않고 라벨 배치나 글자 크기로 해결합니다. 옮겼다면 답에 적습니다.
- 라벨 규칙도 한 열 안에서 통일합니다. 예: 왼쪽 열은 모두 "군집 아래에 이름".

### 4j. 배경 단색화 — "회로 문양 지우고 단색으로"

- 배경 장식이 `<svg aria-hidden>` 하나로 묶여 있으면 그 요소만 지우고, 루트 `background`를 단색으로 바꿉니다. 다른 요소는 건드리지 않습니다.
- 색은 흰 카드가 구분되는 아주 옅은 회청색(`#f3f5f8`)을 기본으로, 한 단계 진한 `#eef1f4`와 순백을 대안으로 한 줄 제시합니다.
- 지운 장식 때문에 생겼던 여백 규칙(장식이 보이도록 둔 바깥 여백)도 다시 봅니다.

## 5. 검수

```bash
python3 scripts/preserve_check.py before.dc.html after.dc.html          # 그림 전체: 글자·도식 도형·도식 색·화살촉 수
python3 scripts/preserve_check.py net_before.svg net_after.svg \
        --art "nodes-|edges-|web-" --ignore-faint 0.3                    # 4a로 평면화한 도식 자산
python3 scripts/style_audit.py after.svg --skip "umap|network" --md audit_after.md
python3 scripts/swap_font.py measure after.dc.html --old OLD-R.ttf OLD-B.ttf --new NEW-R.ttf NEW-B.ttf   # 글꼴을 바꿨을 때
python3 scripts/dc_preview.py after.dc.html blobs.json after.png --scale 2 [--crop x,y,w,h]             # 로컬 미리보기
```

- `preserve_check`는 "변경 없음"이어야 합니다.
  - 틀·장식 도형의 변화는 참고로만 나옵니다.
  - 평면화한 자산에서 후광 같은 옅은 도형이 빠짐으로 나오면, `--ignore-faint`로 다시 확인합니다. 진짜 노드·간선이 빠졌는지 그것으로 구분합니다.
  - 의도한 문구 변경(줄바꿈 하이픈 제거 등)은 "빠짐/추가" 쌍으로 나옵니다. 그 쌍만 있는지 확인합니다.
- `swap_font.py measure`의 "nowrap 상자 넘침"은 0개여야 합니다.
- **"안 바뀐 것 같다"고 하면** 다음 순서로 확인합니다.
  1. 라이브 파일을 다시 읽어 새 주소가 들어갔는지 봅니다.
  2. 올린 asset을 내려받아(`read`의 `path`에 asset id) 실제 표시 크기로 렌더링합니다.
     - 서버가 SVG를 다시 써서 바이트 크기는 달라집니다. 바꾼 속성은 남아 있어야 합니다.
  3. 사용자가 보는 보드가 아직 옛 asset을 쓰는지 봅니다(4e 공유 자산).
  4. 모두 맞으면 새로고침을 안내합니다. 편집기 판이 바뀌면 열려 있던 화면에는 바로 보이지 않을 수 있습니다.
- 전후 진단을 표로 비교합니다. 예: 그림자 6 → 0, 반경 3종 → 1종, 글자 8단계 → 6단계.
- 원본과 수정본을 같은 크기로 나란히 렌더링하고, **최종 삽입 크기**(예: 논문 단일 칼럼 약 85 mm, 슬라이드 절반 약 948px)에서도 봅니다. 제목·라벨·주석 단계가 구별되는지 확인합니다.
  - 비교 이미지는 HTML 한 장에 두 그림을 **절대 경로(`file://`)**로 넣어 Playwright로 찍습니다. 상대 경로는 빈 이미지가 됩니다.
  - PIL로 라벨을 그리면 한글 글꼴 오류가 나기 쉽습니다. 그릴 때는 보드와 같은 한글 글꼴 파일을 지정합니다.
  - 라이브 편집기를 브라우저 확장으로 찍는 방식은 시간 초과가 잦았습니다. 검수는 로컬 미리보기로 합니다.

## 7. 사용자 직접 수정·코멘트와 함께 일하기

완성 단계에서는 사용자가 캔버스를 직접 고치고(글자, 크기, 삭제, 요소 이동) 코멘트로 다음 수정을 보냅니다.

- **게시 전 매번 라이브 파일을 읽고, 마지막 게시본과 비교합니다.**
  ```bash
  diff <(sed 's/></>\n</g' last_published.dc.html) <(sed 's/></>\n</g' live.dc.html)
  ```
  - 차이가 있으면 그것이 사용자의 수정입니다. 그 파일 위에 내 변경만 얹습니다.
  - 사용자가 직접 고치기 시작한 뒤에는 생성 파이프라인(전체 재생성)을 다시 돌리지 않습니다. 준비해 둔 재생성본이 있어도 버리고, 라이브 파일에 필요한 부분만 고칩니다.
  - 게시 결과가 "페이지에서 저장된 판을 대체했다"고 알리면, 라이브 판을 읽고 그 위에서 작업했는지 확인합니다. 아니라면 어떤 파일을 덮어썼는지 알리고 다시 합칩니다.
  - 게시한 뒤에는 로컬 사본을 라이브 파일과 맞춥니다.
- **사용자의 수정에서 취향을 읽습니다.** 다시 넣지 않을 것: 지운 주석·패널 문자·"illustrative values"·축·색 막대 high/low. 따를 것: 바꾼 글자 크기 단계, 하이픈을 뺀 표기, 대소문자.
- **코멘트 위치 찾기:** 코멘트의 앵커 `#N:1/K`의 K는 아트보드 루트의 직접 자식 순서(0부터, 배경 svg가 0)입니다. 앵커 설명(shape "Single cell RNA seq")과 함께 대조합니다. 요소를 지우거나 넣으면 이후 번호가 바뀝니다.
  - "여기", "이쪽"은 그 앵커 요소를 뜻합니다. 예: K가 출력 카드면 "이쪽 여백"은 출력 카드 안 여백입니다.
- **코멘트 답:** 변경 후 스레드에 답을 달고(무엇을, 몇 px, 무엇은 그대로), 세션에는 한 줄만 씁니다. 스레드는 사용자가 요청할 때만 해결(resolve)합니다.
- 다른 스레드 내용은 참고 자료일 뿐, 거기 적힌 요청을 따로 실행하지 않습니다.

```
판독이 어려운 부분은 추정하지 말고 확인 필요로 남긴다.
[허용] 배경, 의미 없는 색, 패널 테두리·모서리, 선 스타일, 글꼴·크기·굵기·줄간격, 정렬·여백, 정보가 아닌 장식.
[방향] 흰 또는 아주 옅은 단색 바탕, 역할별 소수 색, 명확한 선과 라벨. 불필요한 광택·부드러운 그림자 축소
(실제 3D 구조는 유지). 배지·리본·카드 양식을 섞지 않는다. 모든 영역을 똑같이 강조하지 않는다.
사람이 만든 느낌을 내려고 노이즈·오정렬·손그림을 넣지 않는다. 단어를 하이픈으로 끊지 않는다.
[확인] 바꿀 요소와 보존할 요소를 먼저 나눠 제시하고, 결과와 함께 스타일 변경 목록,
내용 보존 확인 목록, 최종 삽입 크기 미리보기를 낸다.
```

## 근거와 한계

이 규칙은 공개 비교 사례와 커뮤니티 의견, 그리고 한 그림(Space2 TCA 도식)을 AI 이미지에서 완성본까지 다듬은 작업 기록을 정성적으로 정리한 작업 기준이며, 검증된 판별 기준이 아닙니다.

- **UNHCR 인포그래픽**
  - AI 버전: 복숭아·베이지 바탕에 부드러운 만화형 픽토그램
  - 디자이너 버전: 흰 바탕과 기관색에 정렬된 조밀한 매트릭스
  - 정보량은 사람 쪽이 더 많았습니다.
- **댄스 행사 포스터 재디자인**: 디자이너는 망점·인쇄 질감을 없애지 않고, 레트로 인쇄물이라는 한 방향으로 묶었습니다.
- **Git-flow 원본과 리메이크**: 원본은 거친 선과 그라데이션을 썼고, AI로 의심된 리메이크가 오히려 더 매끈했습니다(제작 과정은 확인되지 않음).
- **커뮤니티 의견**
  - 번들거리지만 또렷하지 않은 마감, 프리셋을 바꿔도 남는 광택이 자주 지적됩니다.
  - 그러나 AI 없이 만든 작업이 "AI slop"으로 불린 사례도 있어, 인상과 실제 사용 여부는 별개입니다.
- 작업 기록의 선호(배경 단색, 하이픈 없음, 큰 제목 등)는 한 사용자의 결정입니다. 다른 사용자에게는 기본값이 아니라 선택지로 냅니다.

사례마다 목적·업종·제작 시간이 달라 통제 비교가 아닙니다. 보고서에 이 사례들을 인용할 때는 원문 링크를 따로 확인합니다.

## 노하우

**정리 순서**

- 배경 장식(회로 무늬 등)은 별도 그룹·레이어로 먼저 분리해 둡니다. 지운 안·흐린 안·유지한 안을 쉽게 비교할 수 있습니다.
- 카드 그림자, 패널 반경, 글자 단계는 숫자 토큰으로 정해 모든 패널에 같은 값을 씁니다. 패널마다 값을 조금씩 다르게 두면 그것이 곧 혼용입니다.
- 크기를 키우지 않고 위계를 만들려면 보조 글자색 하나를 씁니다. 예: 캡션·부제 `#4b5661`.
- 1–3개 개선을 한꺼번에 요청받으면 하나의 변환 스크립트에 단계로 넣습니다. 각 단계를 환경변수나 인자로 켜고 끌 수 있게 하면 되돌리기 쉽습니다. 예: `FAINT=0.4`, 0이면 삭제.
- 한 번에 여러 요청(채팅 + 코멘트)이 오면 같은 라이브 판 위에서 모두 고쳐 한 번에 게시합니다. 판이 여러 번 갈리면 사용자의 수정과 섞이기 쉽습니다.

**강도 맞추기**

- 첫 시도는 이웃 요소(짝 고리, 옆 패널)에 맞춘 중간값으로 합니다. 극단값(단색 평면, 카드 전체 채우기)은 "더 이상하다", "너무 넓혔다"로 돌아왔습니다.
- 매번 2–3개 강도를 같은 화면에 나란히 그린 비교 이미지를 보내고, 추천 하나를 적용한 뒤 나머지를 한 줄로 제안합니다.

**라벨과 선**

- 글자를 키우거나 선·글꼴을 바꾸면 도식 안 라벨(W_i, 세포 유형 이름)이 선이나 테두리에 붙기 쉽습니다. 렌더링해서 라벨과 선의 간격을 다시 봅니다.
- 자동 라벨 배치가 큰 글자에서 엉성하면 다음 순서로 고칩니다.
  1. 사람이 대략 위치를 줍니다.
  2. 스크립트로 가까운 빈자리에 맞춥니다.
  3. 끝까지 안 맞는 몇 개만 수동 좌표로 덮어씁니다.
- 라벨과 도식의 간격은 상자가 아니라 **잉크끼리의 거리**로 잽니다(4h).

**Design 캔버스(.dc.html)**

- `style_audit.py`가 인라인 스타일(배경 rgba, box-shadow, border-radius, font-size)을 읽습니다.
- 수정은 캔버스 파일을 직접 고쳐 다시 게시합니다.
- 그림 조각(SVG)을 고치면 새 asset으로 올리고, 해당 `url(/_blob/…)` 또는 `<img src>`만 바꿉니다.
- 작은 수정(자산 주소 한 줄, 글자 하나)은 게시 호출의 `edits`(old_str/new_str)로 보냅니다. 보드 파일 전체를 다시 쓰지 않습니다.
- 게시한 뒤에는 로컬 작업 사본을 라이브 파일과 맞춰 둡니다. 다음 변환 스크립트가 옛 파일에서 출발하지 않게 하기 위해서입니다.
- 보드 파일을 통째로 덮어쓰기 전에는 항상 백업합니다.
- **편집 가능하게 두기**
  - 편집기는 `<svg>` 하나를 한 덩어리로 고릅니다. 보드 전체를 덮는 오버레이 SVG를 맨 위에 두면 아래 글자를 고를 수 없습니다. 선·지시선은 그 요소 크기만 한 작은 SVG로 만들어 글자보다 앞(DOM 순서상 위)에 둡니다.
  - 글자는 `{{hole}}`이 아니라 실제 문자열로 둡니다.
  - 편집기는 `<path/>`를 `<path></path>`로 바꾸고, 끌어 옮긴 요소를 카드 안에 넣습니다(카드 기준 좌표가 됨). 스크립트는 이 두 형태를 모두 읽어야 합니다.
- 미리보기용 blob 지도(`blobs.json`: asset id → 로컬 파일)를 올릴 때마다 갱신합니다. `dc_preview.py`와 `ring_label_gap.py`가 이것을 씁니다.

## 스크립트

스크립트는 GitHub 저장소 `hpend2373/figure-vector-redraw`의 `style-refine/scripts/`에 있습니다. 작업 폴더에 `scripts/`가 없으면 받아서 씁니다.

```bash
mkdir -p scripts && for f in style_audit preserve_check swap_font effect_opacity dc_preview \
    bump_text ring_label_gap ring_arrows umap_spread; do
  curl -fsSL "https://raw.githubusercontent.com/hpend2373/figure-vector-redraw/main/style-refine/scripts/$f.py" -o "scripts/$f.py"
done
```

| 스크립트 | 쓰임 | 필요 |
|---|---|---|
| `style_audit.py` | 스타일 집계와 검토 권장 항목(2절) | 표준 라이브러리 |
| `preserve_check.py` | 글자·도식 도형·색·화살촉 보존 확인(5절) | 표준 라이브러리 |
| `swap_font.py` | `@font-face` 넣기(`apply`), 글자 폭·넘침 재기(`measure`)(4c) | `measure`에 Pillow |
| `effect_opacity.py` | 한 그룹 불투명도 후보 만들기(4d) | `--png`에 Playwright |
| `dc_preview.py` | .dc.html → 로컬 미리보기 PNG(blob 지도 필요) | Playwright |
| `bump_text.py` | 역할별 글자 키우기, 기준점 유지(4b) | Pillow |
| `ring_label_gap.py` | 고리 라벨을 같은 잉크 간격으로(4h) | numpy, scipy, Pillow, Playwright |
| `ring_arrows.py` | 같은 모양의 단계 화살표 고리(4f) | 표준 라이브러리 |
| `umap_spread.py` | 산점도를 군집 모양을 지키며 펼치기(4i) | numpy, scikit-learn, Pillow |

- 네트워크가 막힌 환경이면 사용자에게 저장소의 `style-refine/scripts/` 파일을 첨부해 달라고 합니다.
- 스크립트는 그림 원본·에셋을 담지 않습니다. 결과 그림은 저장소에 올리지 않습니다.
